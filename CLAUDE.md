# SIX SEVEN — B2B лендинг и блог

Лендинг и блог для леденцов на палочке SIX SEVEN (OEM-бренд, 6 вкусов, 6 персонажей).
Владелец: ИП Аубакиров Канат Садыханулы, Алматы. Аудитория: B2B (аптеки, магазины, сети, кассовые зоны).
Язык сайта и блога: русский. Репозиторий публичный, всё, что в нём, видит весь интернет.

## Структура проекта

- `index.html` — главный файл лендинга (бывший `Main.dc.html` из Claude Design) и точка входа для GitHub Pages. Лендинг правим здесь, кроме блоков между `<!-- SEO:START -->`…`<!-- SEO:END -->` и `<!-- BLOG:START -->`…`<!-- BLOG:END -->`: их перезаписывает сборка.
- `support.js`, `vendor/` — служебные файлы экспорта из Design. НЕ редактировать.
- `assets/` — видео и картинки. Пути только относительные.
- `posts/` — исходники статей блога.
- `blog/` — готовые HTML-страницы блога (`blog/index.html`, `blog/<slug>/index.html`) и RSS `blog/feed.xml`. Генерируются скриптом, руками не править: правки вносить в `posts/` или в скрипт и пересобирать. Исключение — `blog/blog.css`: стили блога, правятся руками.
- `scripts/` — сборка блога `build.mjs` (вспомогательные `markdown.mjs`, `templates.mjs`, `imagesize.mjs`) и проверка `check.mjs`. Команды запуска смотреть в `package.json` (`npm run build`, `npm run check`), не придумывать.
- `site.config.mjs` — адрес сайта (`origin`) и базовый путь (`basePath`), а также метаданные сайта: название, автор, описания, OG-картинка, теги подтверждения поисковиков. Менять только здесь, не размазывать по файлам.
- `sitemap.xml`, `robots.txt` — обновляются сборкой.
- `.nojekyll` — нужен GitHub Pages, не удалять.
- В `Лендинг Six Seven (B2B)-html.zip` (исходный экспорт) не лезть и в git не добавлять.
- Лишних зависимостей и фреймворков не добавлять без согласования.

## Дизайн (не менять без просьбы)

- Фон тёмный `#1E1F26`, акцент жёлтый `#FFD22E`.
- Шрифты: Oswald (заголовки), Pacifico (рукописные акценты), JetBrains Mono (моно-подписи).
- Стиль: liquid glass (класс `.glass`), зерно-оверлей, крупные заголовки.
- Адаптив обязателен: ломаные точки 1023px и 640px.
- Видео: `autoplay loop muted playsinline`. Тяжёлые видео не добавлять без сжатия.

## Жёсткие правила контента

- Не выдумывать факты, цифры, цены, сертификаты, свойства продукта и даты.
- Любое утверждение про мем «67», слово года, происхождение мема — только с проверенным источником и ссылкой. Нет источника — не писать.
- Известный проверенный факт: Dictionary.com выбрал «67» словом 2025 года. Остальное про мем проверять заново.
- Контакты (телефон, e-mail, Telegram, WhatsApp) — плейсхолдеры, пока владелец не даст настоящие. Не подставлять свои.
- Не называть аптечные сети, магазины и партнёров поименно.
- Не публиковать закупочные цены, себестоимость, оптовую лесенку и условия по сетям. РРЦ можно показывать только в том виде, как он уже стоит в лендинге.
- Не писать, что продукт «натуральный», «полезный», «лечебный», «безопасный для детей» и т. п. без документов. Это леденцы, не лекарство и не БАД.
- Не указывать e-mail владельца в коммитах и тексте сайта. Для коммитов использовать noreply-адрес GitHub.

## Работа с Git

- Перед крупными правками показывай план (Plan mode) и жди подтверждения.
- Коммиты маленькие, сообщения на английском в повелительном наклонении («Add blog index»).
- Не пушить в `main` изменения, которые ты не проверил в preview.
- Не удалять файлы и не переписывать историю без прямой просьбы.

## Проверка перед «готово»

1. Открыть страницу в preview, проверить, что видео и картинки грузятся (нет битых путей).
2. Проверить мобильную ширину 390px.
3. Для блога: у каждой статьи есть `title`, `description`, `canonical`, JSON-LD (Article, BreadcrumbList), после пересборки она есть в `sitemap.xml`, все факты со ссылками.
4. Пробежаться по списку правил «Жёсткие правила контента» ещё раз.

## Секреты

- Если появятся ключи или токены: только в `.env.local`, он в `.gitignore`, в репозиторий не попадает.
- Настоящие ключи — только в `.env.local` и в настройках Vercel (Environment Variables). В код и в браузерный JS их не класть.
- Строка в этом файле «не читай .env» — не защита. Защита — `permissions.deny` в `.claude/settings.json`, который коммитится. В `.gitignore` держать только `.claude/settings.local.json`, а не всю папку `.claude/`.
